# 구단 시세판 (fco-trading)

FC온라인 구단주들의 구단 가치, 보유 선수 시세, 공식경기와 상대전적을 보는 휴대폰용 웹 페이지.

- 주소 : https://donghary.github.io/fco-trading/
- 구단주 : 456화이팅, 우끼끼하하, 게임좀그만해라, 이게임초보인데 (`app.py` 의 `OWNERS`, 추가 방법은 8.)
- 서버 : 없음. GitHub Actions 가 30분마다 JSON 을 새로 만들어 GitHub Pages 에 올림
- 설치 : 휴대폰 브라우저의 "홈 화면에 추가"로 앱처럼 씀

Data based on NEXON Open API.

## 1. 화면

| 화면 | 주소 | 내용 |
|---|---|---|
| 구단 | `#/` | 구단주별 구단 가치, 1일 전과 7일 전 대비 등락, 순서 변경, 어제보다 많이 오른 선수 |
| 구단주 | `#/o/번호` | 선수 시세(현재가, 1일 전, 7일 전, 오버롤, 급여), 선발 11명 급여 합계, 구단 가치 차트 |
| 공식경기 | `#/o/번호/off` | 시즌별 전적, 리그 경기 분리, 경기별 골 기록과 상대 명단(시세, 급여) |
| 관심선수 | `#/o/번호/watch`, `#/watch` | 구단주별 관심선수, 선수 검색과 저장 |
| 선수 | `#/p/spid/강화` | 시세 차트(24시간, 7일, 30일, 1년), 능력치, 특성, 급여 |
| 상대전적 | `#/h2h` | 구단주끼리 1대1 전적, 승률, 골 종류와 비율, 중거리 골 |
| 구단 검색 | `#/find` | 아무 구단주 닉네임으로 최근 명단과 구단 가치 조회 |

선수 표기 순서는 모든 화면에서 시즌 배지, 강화 배지, 선수명, 급여임 (골 기록 제외).

## 2. 갱신 구조

| 단계 | 내용 |
|---|---|
| 예약 | Cloudflare Worker `fco-search` 가 매시 5분, 35분에 GitHub `repository_dispatch`(refresh) 요청 |
| 생성 | `.github/workflows/update.yml` 이 `python3 app.py build` 실행 |
| 이어받기 | 직전 배포본의 `state.json`(시간대별 시세, 경기 기록, 급여 캐시)을 받아 이어 씀 |
| 배포 | `site/` 를 GitHub Pages 로 올림 |
| 보조 | GitHub 자체 예약(매시 5분), 수동 실행, main 푸시 |

- 넥슨 점검(주로 목요일 패치) 중에는 데이터센터가 403 으로 막힘. 시세를 하나도 못 받으면 배포를 건너뛰고 성공으로 끝냄. 이전 페이지가 그대로 보이고 실패 메일은 오지 않음
- 넥슨 오픈 API 경기 기록은 최근 약 30일만 받을 수 있음. 받은 기록은 `state.json` 에 계속 쌓음

## 3. 데이터 출처

| 데이터 | 출처 |
|---|---|
| 명단, 경기 기록, 골 위치 | 넥슨 오픈 API (`user/match`, `match-detail`) |
| 현재 시세, 일별 시세 | FC온라인 데이터센터 `PlayerPriceGraph` |
| 능력치, 특성, 급여 | FC온라인 데이터센터 `PlayerAbility` (적응도 5 기준) |
| 선수명, 시즌, 포지션 | 넥슨 메타 JSON (`meta_*.json`, 하루 1번 새로 받음) |

## 4. 계산 규칙

- 구단 명단 : 가장 최근 경기의 출전 18명
- 구단 가치 : 명단 18명 시세 합계
- 오버롤 : 적응도 5 는 항상 반영, 풀케미는 따로 더함
  - 구단 선수 : 선발 중 8강 이상 8명이면 8강 이상 +8, 11강 이상 8명이면 11강 이상만 +9
  - 구단 밖 선수(검색, 관심선수) : 본인 강화만으로 금카 +8, 백금카 +9
- 급여 : 카드마다 고정(강화 무관). 선발 11명 합계 상한 315 (`index.html` 의 `PAY_CAP`)
- 능력치 색 : 130 이상 빨강, 140 이상 어두운 노랑, 150 이상 밝은 노랑, 160 이상 민트
- 중거리 골 : 골문 중앙에서 18m 이상, 박스 안팎 무관
- 등락 순위 : 퍼센트가 아니라 금액 기준. 등락순 정렬은 오르내림 상관없이 움직인 금액이 큰 순, 많이 오른/내린 선수도 금액순
- 시즌 : 구단주 본인 쪽 경기의 시즌 번호. 202606 은 "2026-6차"로 표기
- 리그 : 다른 시즌 번호 기간 안에 끼어 있는 번호. 전 시즌 마감 등급으로 이름을 붙임 (챌린저 이상 레전더리 리그, 월드클래스와 마스터 월드클래스 리그, 프로 이하 프로 리그). 시즌 전적에서 뺌
- 상대전적 : 구단주 중 2명 이상의 1대1(클래식, matchtype 40) 기록에 있는 경기
- 경기 시각 : 넥슨은 UTC. 화면은 한국 시각(+9시간)

## 5. 파일

| 파일 | 역할 |
|---|---|
| `app.py` | 데이터 수집과 정적 사이트 생성 |
| `index.html` | 화면 전체 (HTML, CSS, JS 한 파일, 의존성 없음) |
| `watchlist.json` | 구단주별 관심선수 `{구단주: [{spid, grade}]}`. 페이지에서 저장하면 이 파일이 커밋됨 |
| `baselines.json` | 게임 안에서 확인한 통산 전적 출발점 (아래 6.) |
| `lock.json` | 관심선수 저장용 GitHub 토큰을 비밀번호로 암호화한 값 |
| `seed_matches.json` | 처음 한 번 쓰는 경기 상세 묶음 |
| `manifest.json`, `icon-*.png`, `favicon.png` | 홈 화면 설치용 |
| `worker/search.js`, `worker/wrangler.toml` | 구단 검색 중계와 30분 예약 (Cloudflare Worker) |
| `.github/workflows/update.yml` | 생성과 배포 |

## 6. 통산 전적 출발점 (`baselines.json`)

넥슨이 주지 않는 30일 이전 기록이나 시즌 전체 전적을 게임 안에서 확인해 넣는 파일. `asof` 이후 경기는 자동으로 더해짐.

```json
{
  "official": { "456화이팅": { "202606": { "w": 18, "d": 2, "l": 12, "asof": "2026-11-18T03:00:00" } } },
  "h2h": { "456화이팅|우끼끼하하": { "w": 60, "d": 5, "l": 40, "asof": "2026-11-18T03:00:00" } }
}
```

- `asof` 는 UTC (한국 시각에서 9시간 뺀 값)
- `h2h` 의 승무패는 앞사람 기준 (위 예시 값은 형식 설명용)

## 7. 관심선수 저장

- 페이지에서 비밀번호를 넣으면 그 기기에서 저장 가능
- 비밀번호로 `lock.json` 의 토큰을 풀어 `watchlist.json` 을 GitHub 에 직접 커밋함
- 토큰 : fine-grained, 이 저장소만, Contents 쓰기. 같은 토큰을 Worker 비밀값 `GH_TOKEN` 으로도 씀
- 토큰을 바꾸면 `lock.json` 과 Worker `GH_TOKEN` 을 함께 바꿔야 함 (안 바꾸면 저장과 자동 갱신이 같이 멈춤)

## 8. 구단주 추가

- `app.py` 의 `OWNERS` 목록 끝에 닉네임을 붙이고 푸시하면 끝
- 다음 실행에서 그 사람의 명단, 공식경기 30일 치, 기존 구단주와의 1대1 30일 치를 받아 옴
- 기존 순서는 바꾸지 않음 (화면 주소 `#/o/번호` 가 목록 순서임). 첫 화면 표시 순서는 보는 사람이 따로 바꿀 수 있음
- 관심선수 목록, 상대전적, 순위는 인원에 맞춰 자동으로 늘어남

## 9. 키와 비밀값

| 이름 | 위치 | 용도 |
|---|---|---|
| `NEXON_API_KEY` | GitHub 저장소 비밀값, Worker 비밀값, 로컬 `api_key.txt` | 넥슨 오픈 API |
| `GH_TOKEN` | Worker 비밀값 | 30분 예약 갱신 요청 |

- 넥슨 키를 바꾸면 GitHub 비밀값과 Worker 비밀값을 둘 다 바꿈
- `api_key.txt`, `worker/.dev.vars`, `worker/.gh_token` 은 `.gitignore` 대상이라 올라가지 않음

## 10. 로컬 실행

```bash
python3 app.py          # 미리보기 : http://localhost:8000, 10분마다 갱신
python3 app.py build    # site/ 한 번 생성
python3 app.py check    # 데이터센터 실제 조회로 파싱 점검
```

Worker 배포 (worker 폴더에서) :

```bash
npx wrangler@3.99.0 deploy
cat ../api_key.txt | npx wrangler@3.99.0 secret put NEXON_API_KEY
```

## 11. 주요 설정값 (`app.py`)

| 이름 | 값 | 뜻 |
|---|---|---|
| `SQUAD_MIN` | 25 | 명단과 경기 목록 확인 주기(분) |
| `MATCH_PER_RUN` | 600 | 실행당 받을 경기 상세 수 |
| `OPP_PER_RUN` | 15 | 실행당 상대 구단 가치를 매길 공식경기 수 |
| `PAY_PER_RUN` | 400 | 실행당 새로 받을 상대 선수 급여 수 |
| `INTRA_DAYS` | 7 | 시간대별 시세 보관(일) |
| `VALUE_DAYS` | 120 | 구단 가치 기록 보관(일) |
| `INFO_DAYS` | 7 | 능력치, 특성 재조회 주기(일) |
